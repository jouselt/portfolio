Case studies

How I approach constraints, architecture, and delivery

Commerce API resilience

Problem

A high-traffic commerce API had no isolation between its downstream dependencies: one slow or failing service could take the whole request path down with it, and production problems were hard to attribute.

Constraints

Live traffic, no ability to pause the product, an existing test contract that had to keep passing, and a third-party auth library that exposed no timeout option at all.

Architecture and depth

Per-backend circuit breakers with opossum across 6 downstream services, an error classification that separates business failures from infrastructure failures, and a fail-fast policy so a broken dependency is cut rather than retried into a cascade. A uniform 10s timeout replaced ad-hoc waits, and the library with no timeout hook was wrapped in a wall-clock cap.

Diagnosis and depth

Production hangs of roughly 18 seconds were traced through 99 APM transaction snapshots in AppDynamics. Separately, 63.6% of application logs were found to be misrouting to stdout, narrowed down by comparing 6 APIs until the cause landed in the collection tier: an AWS ECS / Firelens configuration issue.

Result: A backend where a failing dependency degrades predictably instead of cascading, a request path that cannot hang indefinitely, and logs that can be trusted for diagnosis. Observability was built alongside it: a 40+ event typed logging taxonomy, per-request correlation IDs and PII masking, plus Splunk dashboards adopted across 6+ APIs.

Figma → legacy parity → Stencil pipeline

Problem

A legacy frontend written in PHP was being replaced, and the new component had to preserve behavior that was only documented by the old implementation. Design files described intent; the legacy code described what users actually got. Comparing both by hand, screen by screen, was slow and easy to get wrong.

Constraints

The output had to be a Stencil.js web component reusable across every app, functional parity had to be verifiable rather than assumed, and the migration could not lose features nobody remembered were there.

Architecture and depth

I built an AI-assisted pipeline around an MCP server that reads the Figma designs, compares them against the legacy PHP implementation, and converts the result to Stencil. That turned a manual parity audit into a repeatable pass, and it is the mechanism behind the coverage jump on the ported handlers.

Key decisions

Treat the legacy code as the specification of record and the design as intent, rather than assuming either one alone was complete. Keep the comparison reproducible so the same pass could be re-run as the component grew.

Result: One Stencil component reusable across all apps, with functional parity against the legacy implementation and handler coverage raised from 9.9% to 100% statements.

Quick Quote API

Problem

The quote experience needed a backend path that could safely interpret deep-link parameters and drive users into the right destination state.

Constraints

Input validation, redirect safety, cookie behavior, and production observability mattered as much as the happy path.

Architecture and depth

I designed the endpoint behavior, validation flow, correlation-aware logging, and the Splunk visibility that kept frontend and backend diagnostics traceable. The service ran on Node.js and TypeScript over Restify, behind a BFF layer for commerce APIs.

Key decisions

Chose explicit parameter validation and structured diagnostics over opaque redirects to make support and production troubleshooting faster.

Result: A more accountable quote-entry flow with backend diagnostics designed for real operational support, not just feature completion.

Result: A working bridge for compliant payment interactions in a complex enterprise environment where correctness mattered more than flashy UI.
