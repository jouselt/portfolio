Case studies

How I approach constraints, architecture, and delivery

Quick Quote Vista

Problem

Disney needed a quote experience that could serve multiple regions, brands, and responsive breakpoints without fragmenting the implementation.

Constraints

Cross-brand consistency, locale-specific variants, booking rules, and enterprise quality expectations under active product evolution.

Architecture and depth

I built the component with Stencil.js and Web Component patterns so the same core behavior could be adapted across sites while keeping validation, date selection, and resort selection logic maintainable.

Key decisions

Optimized for reuse and predictable responsive behavior instead of per-market one-offs, then cleaned SCSS and expanded test coverage as complexity grew.

Result: A real multi-variant booking component with 8+ international versions, bug resolution across breakpoints, and stronger maintainability for ongoing product work.

Quick Quote API

Problem

The quote experience needed a backend path that could safely interpret deep-link parameters and drive users into the right destination state.

Constraints

Input validation, redirect safety, cookie behavior, and production observability mattered as much as the happy path.

Architecture and depth

I worked on the endpoint behavior, validation flow, correlation-aware logging, and Splunk visibility so frontend and backend diagnostics stayed traceable.

Key decisions

Chose explicit parameter validation and structured diagnostics over opaque redirects to make support and production troubleshooting faster.

Result: A more accountable quote-entry flow with backend diagnostics designed for real operational support, not just feature completion.

Carnival web ↔ POS payment integration

Problem

Carnival needed the web experience to coordinate securely with POS hardware for payment and signature flows.

Constraints

PCI-sensitive behavior, hardware integration, legacy Verifone compatibility, and support for newer Ingenico devices.

Architecture and depth

I implemented WebSocket communication for web ↔ device messaging and helped connect the user-facing payment journey with lower-level device behavior.

Key decisions

Optimized for compatibility and reliability under mixed hardware conditions, not just greenfield assumptions.

Result: A working bridge for compliant payment interactions in a complex enterprise environment where correctness mattered more than flashy UI.

steer-runtime + MCP servers

Problem

AI-assisted delivery often stays trapped in ad-hoc prompting, making work hard to review, repeat, and scale across a team.

Constraints

Needed repeatability, repository-backed instructions, auditable workflows, and access to the same engineering tools teams already use.

Architecture and depth

I created a layered runtime with 55+ specialized agents plus MCP servers that connect workflows to JIRA, Confluence, Splunk, and GitHub Enterprise.

Key decisions

Moved durable context into specs and structured runtime behaviors so AI support becomes operational engineering infrastructure instead of chat-only assistance.

Result: A reusable applied-AI workflow model focused on delivery quality, team adoption, and traceable engineering decisions.
